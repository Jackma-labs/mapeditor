# 地图生产标准流程

## 1. 采图数据入库

采图设备输出目录中应包含 `ResultOut` 文件夹，系统优先读取其中的 `.las` 文件作为标准点云输入。采图包进入资产库后，后台会自动执行预检、底图瓦片生成和合并底图更新。

当前推荐生产方式是：采图数据统一进入 NAS 或服务器采图入口，由服务器自动同步到 `capture_inbox`，避免多人手动上传大文件。

## 2. 底图生产

每个采图包会生成一套单包底图，合并底图默认命名为 `capture_inbox_merged`。同一采集段重复采集时，自动拼图优先使用最新采图包，旧包仍保留为资产记录，方便追溯。

后台正在生成底图或合并底图时，前台仍可以打开已有底图、标注和仿真；但大规模合并会占用 CPU 和磁盘 I/O，瓦片加载会变慢。

## 3. 人工标注

打开合并底图后进行 Apollo 地图标注。默认车道限速为 `40 km/h`。建议先绘制道路/车道主结构，再补充路口、人行横道、停车位、标志牌、红绿灯等要素。

## 4. 发布地图

标注完成后先保存，再发布地图包。发布物必须包含 `base_map.bin`、`base_map.txt`、`routing_map.bin`、`sim_map.bin`，系统会拒绝不完整发布物进入部署链路。

## 5. ApolloLite 仿真

发布后执行“一键仿真跑图”。系统会同步最新完整地图到 ApolloLite，启动 Routing、Planning、Control，自动生成测试路线并检查车辆是否起步。

## 6. 边缘设备部署

仿真通过后执行边缘部署。部署前需要配置边缘设备 IP、SSH 用户和 Apollo 地图目录。部署历史会记录每次结果，必要时可以回滚。
